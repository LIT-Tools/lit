## Правила, которые реально сэкономили время

### Git

- **`git reset --hard` + `git clean -fd` — опасная пара.** На шаге 3
  потеряли 7 коммитов и один untracked-файл (`core/`). Для отката
  неудачной попытки — `git checkout . && git clean -fd` (без reset).
  Если нужно откатить **закоммиченное** — сначала `git stash push -u`,
  потом reset, потом `stash pop`.
- **Перед `git clean -fd` — `git clean -fdn`** (dry-run). Сносит
  untracked-файлы, которые нигде не закоммичены.
- **`git show --stat HEAD` перед коммитом.** На шаге 4.5 в коммит
  случайно попал `REFACTORING_LOOP.md`. Один diff — ровно ожидаемые
  файлы.
- **`git status --find-renames`** — при `git mv` должны быть `R`, не
  `D`+`A`. Иначе история теряется.

### uv / Python

- **`uv sync --reinstall-package lit`** — после любой правки
  `pyproject.toml` или `git mv`/`git rm` файлов пакета. Иначе
  `.venv/bin/lit` остаётся старым, smoke врёт.
- **Битый `.venv`** (linux-путь, pyenv-путь) → `rm -rf .venv && uv sync`.
  Не редактировать `.venv/` руками. Один раз `uv python pin 3.12` —
  фиксирует версию.
- **`from __future__ import annotations`** — первая исполняемая строка
  (после docstring, до остальных `import`). Иначе `SyntaxError`.
  Нужен для `X | None` при `requires-python = ">=3.9"`.

### Моки и тесты

- **`patch("lit.X")` работает только если `X` в namespace `lit`.**
  Поэтому re-export из `core`/`integrations` в `lit.py` — не «грязь»,
  а контракт с тестами. Удалишь re-export — моки перестанут бить в
  цель (тихий баг: тест «проходит» по неправильной причине).
- **Top-level `from lit import X` в подпакетах = циклический импорт.**
  Только deferred (внутри метода). Это не стилистика — единственный
  способ сохранить моки `patch("lit.X")` и не уронить импорт.
- **`sys.modules[__name__] = _m`** — способ сохранить старую модульную
  точку для моков. Обычный `from X import *` в шиме **не работает**:
  `patch("old.X")` бьёт в шим, а оригинал (`new.X`) остаётся настоящим.
  Применяли на шаге 4, удалили на 4.5. Если снова понадобится —
  с комментарием и датой удаления.
- **`_save` мокать**, а не `builtins.open` — не зависишь от
  существования `~/.lit/`.
- **`print + return`, не `raise`** — если валидация внутри метода с
  внешним `try/except Exception`. Иначе внешний except перехватит и
  напечатает второе, менее понятное сообщение.
- **`echo exit=$?` на каждой команде.** Traceback = провал, даже если
  exit=0.

## Чего не делать

- **Не править тесты, чтобы они прошли.** Если мок сломался — правится
  потребитель (deferred import, re-export), а не тест. Исключение —
  отдельный явный шаг «перевести тесты на новый namespace» (как 4.5).
- **Не смешивать перемещение файлов и изменение логики** в одном шаге.
  Шаг должен быть атомарным — иначе history нечитаема, а откат
  болезненный.
- **Не «оптимизировать» deferred-импорты** на top-level ради
  «чистоты» — сломает и моки, и цикл импортов.
- **Не удалять re-export** в `lit.py` / `lit/__init__.py`, пока
  существуют `patch("lit.X")` в тестах.

## Как заполнять этот файл (для следующего цикла)

Файл — не история (её знает `git log`), а **сжатая памятка для
следующих циклов**. Одна секция на **цикл**, не на шаг.

Шаблон секции:

```markdown
## <Название цикла> (<YYYY-MM>)

### Уроки
- <правило, применимое к будущим циклам>

### Чего не делать
- <анти-паттерн + короткая причина>

### Открытые вопросы
- <что отложено, куда смотреть>
```

Правила:
- **Максимум 5–7 пунктов** в каждой секции. Больше — режь.
- **Только неочевидное.** «Не редактировать `.venv` руками» — очевидно,
  не пиши. «`print + return` вместо `raise` в валидации» — неочевидно,
  пиши.
- **Ссылка на код**, а не описание кода: «см. `core/worklog_manager.py
  add_entry`», не «мы добавили try/except вокруг strptime».
- **Не дублировать между секциями.** Правило принадлежит первой секции;
  в новых — ссылка («см. 2026-10 → uv»).
- **Проверять актуальность.** Если правило относится к тому, чего уже
  нет в коде (`sys.modules`-шимы удалены) — либо с пометкой «удалено»,
  либо в «Открытые вопросы» с указанием, почему помним.
- **Не путать с `REFACTORING.md`.** Там — план и «что отложено»; здесь —
  только уроки процесса.
