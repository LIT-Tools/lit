# Конвенция коммитов и рабочий процесс

В проекте используется стандарт **Conventional Commits**.

## 1. Подготовка перед коммитом (ЧЕК-ЛИСТ)

Перед созданием коммита обязательно выполните следующие проверки:

1.  **Проверьте автора**: Убедитесь, что `git config user.name` и `git config user.email` установлены верно (автор должен быть `LEXX <s_kushnarev@rambler.ru>`).
    *   Команда: `git config user.name` и `git config user.email`
2.  **Проверьте ветку**: Убедитесь, что вы не на `master` (коммиты делаются в `dev` или `feature/*`).
    *   Команда: `git branch`
3.  **Оформите коммит**: Используйте формат `<type>(<scope>): <subject>`.

## Формат сообщения

```text
<type>(<scope>): <subject>
```

## Разрешенные типы (`type`)

- `feat`, `fix`, `docs`, `test`, `ci`, `chore`, `refactor`, `style`, `perf`.

## Правила для `subject`

- Императивное наклонение (add, fix, update).
- Строчная буква в начале.
- Без точки в конце.
- Язык: английский.
- До 72 символов.

## Merge-коммиты

Merge-коммиты не подчиняются этой конвенции.
